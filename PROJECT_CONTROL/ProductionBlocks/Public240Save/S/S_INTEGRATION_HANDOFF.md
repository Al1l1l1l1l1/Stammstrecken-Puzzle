# S – typisierter Anschluss für spätere I-Montage

S referenziert keine A-Typen. I injiziert den echten A-Publickatalog ausschließlich als T-IPublicPuzzleCatalog in `ReviewProgressCatalog(publicCatalog,campaignUtf8,completionUtf8,canonicalJson)`. Die beiden eigenen UI-Katalogquellen sind DRAFT/IsolatedReview; Completionidentity hasht die vollständige Reviewwrapperquelle einschließlich der 240 Nullsternzeitrecords. `CatalogSet` bindet die drei getrennten Teilidentitäten. Kein Produkt-/Fixturestatus wird promoviert.

`LocalProgressPolicy(publicCatalog,review.Campaign,review.Completion,canonicalJson,new SaveLedgerCodec(canonicalJson))` enthält die reine Fortschrittsprojektion. `LocalSaveCodec` erhält dieselben Ports, Profil-/Katalogbindungen und ausschließlich ausdrücklich unterstützte historische Lesedeskriptoren; optional leer bedeutet keine erfundene historische Policy. Die QA-Profilnamespace bleibt `qa-public240-v1` mit IsolatedReview. Root liefert SaveFileSystem und AtomicSaveRepository; deren aktueller gemeinsam geprüfter Stand ist für I maßgeblich.

`PersistedPuzzleSession(repository,publicCatalog,policy,profile,catalogSet,clock,dispatcher)` stellt Read-/Command-/Savegrenze bereit. Clock.MonotonicMilliseconds kommt aus der Prozessmonotonie, UtcNow dient nur Diagnose beziehungsweise ausdrücklich angenommener Draftretention. Dispatcher.InvokeAsync muss Actions tatsächlich auf den logischen Haupt-/Applicationthread zurückstellen; bloß Task.CompletedTask auf einem Worker wäre kein korrekter Platformadapter. Start, RestoreDraft und Handle werden durch den Host auf diesem Applicationloop aufgerufen. File-/Codec-/Hasharbeit gehört auf Worker; S übernimmt schwere reine Saveprojektionen selbst ausdrücklich per Task.Run.

Der Host lädt zunächst über LoadAsync. NeedsInitialization öffnet ausschließlich einen eigenen ausdrücklich gewählten CreateProfileAsync-Pfad. Vorhandene fehlerhafte Daten führen nicht zu automatischer Initialisierung oder Reset. ConfirmedResetCorruptProfileAsync ist der getrennte, vorher sichtbar bestätigte Neustartbefehl; Unknown/Failed bleiben geschützt. Failed-/unbestätigte Saves geben keine Ergebnisfahrt frei.

Für Autosave wird genau ein AutosaveCoordinator an den Usecase gebunden. NotifyMutation wird nur nach einer tatsächlich veränderten Domainrevision aufgerufen; Auswahl und No-op erzeugen keine Dirtyrevision. TickAsync erhält denselben Prozessmonotoniewert. Lifecycle: zuerst realen PauseForLifecycle-Command mit dem aktuellen monotonen Instant anwenden, tatsächliche Änderung notifizieren, danach FlushAsync anfordern. Resume verwendet einen frischen Prozessanker. Kein Render-/Updatepfad führt direkte File-I/O aus.

Beim echten SolvedPendingCommit wartet CommitCompletionAsync auf ältere Draftwrites. Erst CanPresentResults erlaubt Ergebnis-/Reward-/Fahrtpräsentation für die genaue gegenwärtige Session. Snapshot ist ausschließlich der letzte bestätigte immutable Zustand. Bei Failure bleibt der gelöste Versuch für einen zulässigen Retry erhalten; nach ungewisser Wirkung wird vor jeder weiteren Mutation frisch geladen. Ein erfolgreicher autoritativer Reload kann den alten Versuch bewusst ablösen, aber bestätigt ihn nicht nachträglich.

Conflict invalidiert die alte Basis und löst zwingend einen frischen vollständigen Load aus. RecoveryObservation ist nur zum Loadzeitpunkt gültig, keine frühere Commitlock-Beobachtung. Die UI stellt eine neue sichtbare Kandidatenwahl her und übergibt SaveRecoveryRequest. RecoverAsync bleibt read-only; PromoteRecoveryAsync schreibt danach ausschließlich das exakt ausgewählte Payload mit neuer höchster Generation. Erst bestätigte Promotion öffnet neue Commands. Ein Conservativemain bei SplitBrain ist keine autoritative Gameplaybasis. Cancellation/Failure/unvollständige Beobachtung behalten die Sperre.

Alle gespeicherten Hint-/Daily-/Endless-/Reward-/Cosmetics-/IAP-/Privacyzustände bleiben passive Daten. S startet keine Provideroperation, Generierung, Käufe, Ads, SDKs oder Analytics. Der gemeinsame regulatorische Produkt-/Geräte-/Humanreviewstatus entsteht außerhalb dieser S-Lieferung.
