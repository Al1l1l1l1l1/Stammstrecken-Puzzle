# R – konkrete plattformgebundene Writer-Sperre vor deren Code

R/Codex nimmt die getrennte S_OS_HANDLE_PRECODE_REVIEW.md/.json innerhalb MANUS-2026-10-19-01 Abschnitt5 und ADR035 zuständig an. Keine Produkt-/Architektur-/Profilrechte werden verändert, keine Assemblykante entsteht. Die Änderung betrifft allein die eigene neue SaveFileSystem.cs.

Windows verwendet das bestehende echte benannte Betriebssystemmutex. Linux/Android und Apple erhalten stattdessen eine exklusive nichtblockierend versuchte flock-Sperre auf einen eigenen read-only geöffneten Deskriptor des fest gebundenen bereits vorhandenen privaten Rootverzeichnisses. Das serialisiert konservativ alle Profile dieses Roots, ohne ihre Identitäten oder Speicherpfade zu vermischen. Prozessabbruch beziehungsweise Deskriptorschluss gibt die Betriebssystemsperre frei. Cancellation und ein benannter 30-Sekunden-Timeout bleiben vorgeschrieben. Unbekannte API-/Filesystemunterstützung scheitert benannt und geschlossen; keine Rückstufung auf eine nur prozesslokale Mono-Sperre.

Der unveränderlich gebundene private Root muss vor Konstruktion existieren. Eine ausdrückliche statische Infrastrukturprovisionierung im allein zuständigen FileSystem darf ihn auf einem Worker anlegen, erzeugt aber keinen Profilunterbaum und keine Save-/Lockdatei. Load und Recover sowie der FileSystemkonstruktor erzeugen selbst weder Dateien noch Verzeichnisse. I ruft diese ausdrückliche Rootprovisionierung später auf seinem Worker auf. Tests bereiten den Root vor Beginn des geprüften Read-only-Vorgangs ausdrücklich vor. Symlinks/Reparsegrenzen werden weiterhin geprüft.

Die Primärbelege und ihre Grenzen stehen vollständig in der getrennten Vorcodereview. Die technische Umsetzung benötigt konkrete Windows-Interprozess-, Linux-FFI-/Interprozess-/Crashrelease-/Cancel-/Read-only-Nachweise und die regulären Builds. Insbesondere ist damit noch kein iOS-APFS-Geräte-, Android-Hardwarekill- oder allgemeiner Unix-PASS erklärt. Historische Dateisystem- und Teststände bleiben erhalten.
